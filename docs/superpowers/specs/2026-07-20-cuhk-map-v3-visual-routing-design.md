# CUHK Campus Map V3 视觉与路线设计

**日期：** 2026-07-20  
**状态：** 已确认  
**目标：** 将 V2 调整为以 CUHK 官方校园 PDF 为信息逻辑、以 prettymaps 为视觉语言的白底 2D 校园地图，并完善天桥、楼梯和校巴方向表达。

## 1. 范围

V3 包含以下工作：

1. 采用白色校园底图，移除大面积绿色填充。
2. 使用官方 `campus_id` 按书院或校园区域为建筑着色。
3. 区分普通步道、天桥和楼梯，并按照官方 PDF 补齐 OSM 缺失的连接线。
4. 将校巴开关升级为线路筛选器，并沿线路显示方向箭头。
5. 从界面和启动流程停用 3D，同时明确记录现有卡屏问题。

V3 不修复 3D 渲染问题，不实现路线规划，也不从 PDF 自动生成完整地理数据。

## 2. 视觉方向

采用已确认的“A：官方 PDF × prettymaps”方向：

- 校园主体和未分类区域使用白色 `#FFFFFF`。
- OSM `green` 和 `forest` 不再绘制大面积绿色填充或绿色点阵。
- 运动场等有明确功能的区域可保留极浅绿色；水体保留浅青色。
- 道路使用官方 PDF 的浅蓝灰 `#A5BFD2`，主次道路仅以宽度区分。
- 建筑保留清晰白色描边，以书院或校园区域色作为主要填充。
- POI、弹窗和顶部控件使用中性深灰，避免与书院色竞争。

## 3. 建筑区域数据

官方建筑点已经包含 `campus_id`。数据管线把该字段传递给 OSM 建筑面：

1. 官方点落在某一建筑面内部时，优先匹配该建筑面。
2. 否则在既有距离阈值内匹配最近建筑面。
3. 多个官方点命中同一建筑时，采用距离建筑质心最近的记录。
4. 未命中的建筑保留空区域标识并使用回退色。

建筑功能分类和区域分类由同一次空间匹配生成，避免两套匹配逻辑产生不同归属。

## 4. 天桥、楼梯与普通步道

V3 生成统一的 `pedestrian_links.geojson`，每条要素至少包含：

- `kind`: `bridge` 或 `stairs`；
- `source`: `osm` 或 `official_pdf`；
- `name` 或 `note`: 可选的人类可读说明；
- `geometry`: `LineString`。

来源分为两部分：

1. **OSM 自动识别**
   - `highway=steps` 识别为 `stairs`；
   - 步行类道路带 `bridge=yes`、正 `layer` 或等价天桥语义时识别为 `bridge`；
   - 数据抓取和写出过程保留识别所需的 OSM 标签。
2. **PDF 人工补齐**
   - 在受版本控制的 GeoJSON 中逐条校准 PDF 中存在但 OSM 缺失的连接线；
   - 人工数据与 OSM 数据合并前做字段、几何类型和校园范围校验；
   - 重叠要素按空间接近度去重，人工记录优先。

地图样式：

- 普通步道为细灰线；
- 天桥为较粗的实心蓝线；
- 楼梯或明显高差通道为蓝色虚线；
- 天桥和楼梯绘制在建筑层之上；
- 图例明确解释三种线型。

## 5. 校巴筛选与方向

顶部“校巴”按钮改为线路选择器，状态包括：

- 关闭；
- 全部线路；
- 官方数据中的任意单条线路。

默认状态为关闭。单选线路时只显示该线路及相关站点；“全部线路”用于查看整体网络。

数据管线为线路写出稳定的 `route_id`，并根据线路分段的起止站关系为站点写出 `route_ids`。路线、站点和方向箭头共用同一筛选状态。

方向箭头使用 MapLibre 沿线符号层重复绘制，方向来自官方有序线路几何本身。箭头图像在浏览器中本地生成，不引入网络字体或外部图片。路线弹窗继续显示中英文线路名；站点弹窗继续显示中英文站名。

当数据加载失败时，地图主体仍可使用；校巴控件保持关闭或禁用，并在控制台记录清晰警告。

## 6. 3D 状态

V2 存在以下未修复问题：切换到 3D 后渲染可能卡住，切回 2D 不能恢复。

V3 的缓解措施：

- 页面不显示 3D 按钮；
- 启动流程不注册 3D 切换事件；
- 正常 UI 路径不调用 `map.setTerrain`；
- 3D 建筑层保持不可见；
- 在 `cuhk/KNOWN_ISSUES.md` 记录状态、复现步骤、影响和当前缓解措施；
- README 移除 3D 功能声明并链接已知问题。

地形数据生成代码可以保留，以便未来单独调查，但不属于 V3 的用户功能。

## 7. 组件边界

- `pipeline/building_types.py`：官方建筑点与 OSM 建筑面的统一匹配，并写出功能分类和区域标识。
- `pipeline/layers.py`：保留道路标签并识别 OSM 天桥、楼梯。
- 新的行人连接模块：加载人工 GeoJSON、合并 OSM 连接、去重和校验。
- `pipeline/official.py`：写出校巴 `route_id`，计算站点 `route_ids`。
- `site/style.json`：白底、书院色、天桥/楼梯图层和校巴方向符号层。
- `site/app.js`：线路选择状态、MapLibre 过滤器、箭头图像和弹窗交互。
- `site/index.html`：线路选择器、图例和隐藏 3D 控件。

## 8. 测试与验收

测试优先覆盖以下行为：

1. 建筑匹配正确传递 `campus_id`，且不破坏现有 `bt` 分类。
2. `steps`、`bridge=yes` 和普通步道得到不同分类。
3. 人工连接 GeoJSON 只接受校园范围内的 `LineString` 和合法 `kind`。
4. 人工连接与 OSM 连接合并时能够去重。
5. 官方校巴路线包含 `route_id`，站点包含正确的 `route_ids`。
6. 样式背景为白色，完整覆盖全部区域色，天桥与楼梯线型不同，3D 默认不可见。
7. 前端没有可见 3D 控件；关闭、全部线路和单线状态使用一致的路线、站点、箭头过滤器。

实现完成后运行：

- CUHK 全量 Python 测试；
- JSON 解析和 JavaScript 语法检查；
- 数据管线构建与现有数量下限校验；
- 本地浏览器的 2D、捷径、单条校巴和全部校巴视觉检查。

## 9. 成功标准

- 默认地图没有大面积绿色底色，整体观感与确认的 A 方案一致。
- 建筑颜色能直接表达官方书院或校园区域归属。
- 用户能从线型区分普通步道、天桥和楼梯。
- PDF 中重要但 OSM 缺失的天桥和楼梯可以通过受版本控制的数据补齐。
- 用户能选择全部或单条校巴线路，并看见可靠的行驶方向箭头。
- 用户无法通过正常界面触发已知 3D 卡屏问题，且该问题有明确文档记录。
